# Admission payment display and optional stay tracking

Reservations retain their original online/counter payment choice and payment history. Staff display now also checks saved admissions for each reserved child, in the same household, Square environment and Eastern calendar day. All reserved children must have a settled paid/prepaid/included admission before a counter reservation displays settled. Partial payments, other families, other days and test-environment records cannot clear a due label. Conflicting duplicate admissions require review. This projection is read-only and never charges, waives, or rewrites financial records.

The check-in cards label `prepaid` as **Paid in advance**. Existing paid states (`paid`, `walkin_paid`, `terminal_paid`) remain paid even if the original charged price is retained for reporting. Reservation cards in search and the Open Play calendar use the same projection, including **Admission paid in Square — do not collect again** for a settled counter visit. Real production data validation identified five counter reservations with completed admission payments whose stored booking choice still said due.

Check-out is optional. Active cards display names and payment state, with no live arrival/duration timer. Only an explicit checkout reveals the saved arrival, departure and duration. Stay statistics already exclude incomplete durations; the incomplete-visit reminder is now removed. No invented departure times are saved, and original attendance/payment records remain intact. Today's list is limited to the current Eastern day, so unclosed visits do not accumulate in later days.

An active iPad shift now offers **Continue to my dashboard**, using the same role-appropriate destination as PIN clock-in. Returning to the dashboard does not restart a shift or modify timecards. The payment panel identifies **Home Screen app** versus **browser tab** from actual iPad display mode. A shortcut created in Safari can still launch an independent web app: `/staff-login` explicitly uses `appleWebApp.capable=true` and `staff.webmanifest` sets `display=standalone`. Safari browser tabs and an installed app can have separate session storage.

The preceding emergency release fixes the ambiguous `checkins -> people` embed (`child_id` and `person_id` both exist) by reading `checkins.person_id` explicitly and resolving the family in a separate query. Reopening the app was only the trigger for reloading that faulty query.
