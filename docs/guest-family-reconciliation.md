# Guest waiver family reconciliation

Public `/waiver` still saves its signed receipt atomically using the existing submission RPC. A `waitUntil` task reconciles matching guest-only families afterward, so private identity lookups do not delay the receipt. Receipt-status retries also retry linking. No database migration or new authentication grant is required.

A match requires the same normalized guardian name, a matching contact (household phone/email or a confirmed caregiver's Auth email), and a unique compatible match for every submitted child. Accents, whitespace and US phone punctuation normalize. An existing blank child surname can match an exact first name and birthdate. A missing birthdate requires an exact full child name plus verified caregiver email or both contact fields. Conflicting birthdates, duplicate child identities, multiple candidate accounts, and unmatched children remain for review. Names alone never link families.

Sources with account members, reservations, membership/billing records, class registrations, verified guest identities or check-ins are excluded from automatic reconciliation. Each accepted waiver keeps the same ID, signature, signing/expiry times, consent and original legal/child snapshot. Its household and covered-person IDs are mapped together to the existing family's signed children only. An additional `agreement_snapshot.family_reconciliation` audit preserves the original household, covered IDs and person mapping. Original households/people remain recoverable. Party roster links follow the same waiver ID. The existing staff directory alias is written last to suppress the duplicate search result; retries can finish an interrupted write using the saved audit. This is a staged, idempotent REST workflow, not a cross-table SQL transaction. Errors preserve the signed receipt and leave unfinished directory work reviewable.

The public response contains no matching family ID, children, account existence or linking result. Submitted contact information cannot read an account, change its members, claim its verified email identity, or grant access. Linking changes no price, payment or visit count.

The check-in desk uses one reservation/search list containing both today's booked families and walk-ins. Checked-in cards have a green background and the existing idempotent checkout action; departed cards are gray and retain arrival/departure/stay times. Other families use dark bold names. Duration statistics remain available below the workspace.
